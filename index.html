HAFTA 1

Dosya organizasyonuna giriş

Dosya organizasyonu

Verileri kalıcı ortamda saklama, düzenleme, arama, güncelleme ve silme yöntemleridir. Hedef yalnızca alan tasarrufu değil, özellikle fiziksel erişim maliyetini azaltmaktır.

Temel kavramlar

Alan (field): tek özellik. Kayıt (record): alanların bütünü. Dosya (file): kayıt topluluğu. Anahtar (key): kaydı tanıtan veya aratan değer. Probe: bir konumu kontrol etme.

RAM ve disk

RAM hızlı ve geçicidir; disk/SSD kalıcı ve görece yavaştır. Az sayıda rastgele erişim, çok sayıda rastgele erişime tercih edilir.

HAFTA 2

Disk yapısı ve erişim maliyeti

Manyetik disk

Plaka → yüzey → iz (track) → sektör (sector). Aynı yarıçaptaki izler silindiri (cylinder) oluşturur. Kafa doğru ize gider, sektörün dönmesini bekler ve veriyi aktarır.

Erişim süresi

T = seek time + rotational latency + transfer time. Örnek: 5 + 4 + 1 = 10 ms. SSD’de mekanik seek/rotasyon yoktur.

Blok, sayfa, tampon

Blok disk aktarım/yönetim birimidir; sayfa mantıksal işleme birimi olabilir. Buffer, RAM’de geçici alandır; küçük I/O işlemlerini birleştirip disk erişimini azaltabilir.

HAFTA 3

Dosya işlemleri ve arama

Dosya işlemleri

open dosyayı açar; read okur; write yazar; seek konumu değiştirir; tell konumu bildirir; close kapatır; EOF dosya sonuyla ilgilidir. C++: seekg/tellg okuma; seekp/tellp yazma konumu.

Metin ve ikili kip

Metin dosyasında 123 üç karakter olarak saklanabilir. İkili dosyada 32-bit tamsayı tipik olarak 4 bayttır; ikili gösterim platforma bağlı olabilir.

Sequential search

Sırasıyla her kayıt incelenir; sıralama gerekmez. En kötü durumda O(n) karşılaştırma.

Binary search

Sıralı kayıt ve etkin rastgele erişim gerekir. Her adımda aralık ikiye iner; O(log n) karşılaştırma.

Interpolation search

Sıralı sayısal anahtarların dağılımına göre konum tahmin edilir; yaklaşık düzgün dağılımda avantajlı olabilir.

Self-organizing search

Move-to-front: bulunanı başa alır. Transpose: öncekiyle değiştirir. Count: erişim sıklığına göre düzenler.

HAFTA 4

Kayıt yapıları ve hashing

Sabit uzunluklu kayıt

Her kayıt B baytsa, başlangıç ofseti + RRN × B ile konuma gidilir. Avantaj: doğrudan erişim. Dezavantaj: kullanılmayan alan.

Değişken uzunluklu kayıt

Delimiter (ayırıcı) veya length indicator (uzunluk bilgisi) ile kayıt sınırı belirlenir. Alan kullanımında esnek ama konumlandırma daha karmaşık.

Hash fonksiyonu

h(k)=k mod M. Örnek: h(27)=27 mod 10=7. Farklı anahtarların aynı adrese düşmesi collision (çarpışma) oluşturur.

Progressive overflow

Home doluysa sonraki konumlar sırayla denenir; tablo sonunda başa dönülebilir. Kümelenme (clustering) artabilir.

LISCH / EISCH / LICH

LISCH: yeni çarpışan kayıt zincirin sonuna eklenir. EISCH: zincirin başına yakın eklenir. LICH: taşma (cellar) alanından yararlanan late-insertion yöntemidir.

Brent

Çarpışma sırasında mevcut kayıtların taşınması da değerlendirilerek arama/probe maliyeti iyileştirilmeye çalışılır.

Binary Tree hashing

Çarpışmalar hash konumları üzerinde ağaç bağlantılarıyla yönetilir; sıradan binary search tree ile karıştırılmamalıdır. Ders örneğindeki continue/move adımları ve genişlik öncelikli inceleme önemlidir.

HAFTA 5

Dosya sistemleri: inode, FAT, bağlantılar

Dosya sistemi bileşenleri

Superblock genel dosya sistemi bilgilerini, bitmap boş/dolu alanları, inode meta veriyi, veri blokları içeriği tutar.

inode

Dosya türü, boyutu, izinler, sahip, zamanlar, link count ve blok adresleri. Dosya adı genellikle inode’da değil, dizin girdisinde tutulur.

Direct / indirect

Direct pointer doğrudan veri bloğunu gösterir. Single indirect bir adres bloğunu, double indirect iki düzeyli, triple indirect üç düzeyli adresleme yapısını kullanır.

Dolaylı adresleme hesabı

4096 bayt blok / 4 bayt adres = 1024 adres. Tek indirect: 1024 veri bloğu; double: 1024²; triple: 1024³ (bu varsayımlarla).

FAT

File Allocation Table, dosya bloklarının bağlantılarını merkezî tabloda tutar. Örnek: 4 → 9 → 12 → EOF. Ortadaki bloğa erişim zinciri izlemeyi gerektirebilir.

Hard link

Aynı inode’a başka bir dizin girdisi/ad. Hedef dosyanın adı silinse bile diğer hard link çalışır. Yeni hard link link count değerini 1 artırır.

Symbolic link

Hedefin yolunu saklayan ayrı inode’lu özel dosya. Hedef yol kaybolursa dangling symlink olur; hedefin link count değerini artırmaz.

Dosya silme

Son hard link silinse de dosyayı açık tutan bir süreç varsa bloklar hemen serbest bırakılmayabilir.

HAFTA 6

Sıkıştırma: bit, RLE, Huffman, LZ78

Kayıpsız / kayıplı

Lossless sıkıştırmada veri birebir geri elde edilir. Lossy sıkıştırmada bilgi kaybı kabul edilir.

Compact notation

N farklı değer için minimum sabit kod uzunluğu ⌈log₂N⌉ bit. Örnek: 12 değer → 4 bit. Gün 5 + ay 4 + yıl 8 = 17 bit.

RLE

Ardışık tekrarlar değer ve sayıyla gösterilir: AAAAABBB → (A,5)(B,3). Uzun tekrarlar için iyi; dağınık veride büyütebilir.

Escape byte RLE

Kaçış baytı FF ve üçlü FF 24 07 ise 24 baytı 7 defa tekrar edilir: 24 24 24 24 24 24 24.

Huffman

En düşük frekanslı iki düğümü birleştirerek ağaç oluştur; dallara 0/1 ata. Sık semboller kısa kod alır. Prefix-free: hiçbir kod başka kodun öneki değildir. Ortalama uzunluk L=Σ pᵢlᵢ.

LZ78

Tekrarlanan karakter dizilerini sözlükte tutar; tipik çıktı (önceki sözlük indeksi, yeni karakter) çiftleridir.

Sıkıştırma ve erişim

Değişken uzunluklu sıkıştırılmış kayıtlar doğrudan RRN×B adreslemesini zorlaştırabilir.

HAFTA 7

Computed ve Multiple Chaining

Computed Chaining

Zincirdeki sonraki kayda erişmek için doğrudan tam adres yerine pseudo-link ve hesaplama kuralı kullanılır. Bu yöntem ilgili ders notunda hash çarpışmalarını yönetmek için ele alınır.

Multiple Chaining

Ek hash/gruplama mantığıyla kayıtların birden fazla zincir grubunda düzenlenmesi hedeflenir. Yöntemin tablo yerleştirme adımlarını slayttaki örnek üzerinden çalışmak gerekir.

Sıralı arama

Her eleman sırayla kontrol edilir; en kötü durum O(n).

Örnek 3
int sequentialSearch(const int a[], int n, int key) {
    for (int i = 0; i < n; ++i)
        if (a[i] == key) return i;
    return -1;
}

İkili arama

Dizi sıralı olmalıdır. Her turda arama aralığı yarıya iner.

Örnek 4
int binarySearch(const int a[], int n, int key) {
    int low = 0, high = n - 1;
    while (low <= high) {
        int mid = low + (high - low) / 2;
        if (a[mid] == key) return mid;
        if (a[mid] < key) low = mid + 1;
        else high = mid - 1;
    }
    return -1;
}

Progressive overflow (öğretici örnek)

Home doluysa sonraki hücreler denenir. Bu kod kavramsal bir örnektir; slayttaki tam algoritmanın yerine geçmez.

Örnek 5
int hashIndex(int key, int M) { return key % M; }
int insert(int table[], int M, int key, int EMPTY = -1) {
    int pos = hashIndex(key, M);
    for (int probe = 0; probe < M; ++probe) {
        int i = (pos + probe) % M;
        if (table[i] == EMPTY) { table[i] = key; return i; }
    }
    return -1; // tablo dolu
}
